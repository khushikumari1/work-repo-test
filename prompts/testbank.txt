# Core Review & Formatting Rules

## 1. Decision Categories

**KEEP (Retained)** — If the question stem, options, reference, rationale, and answer match the new textbook content in substance (not necessarily exact wording): reproduce every field exactly as it appeared in the input `<ITEM>` (no changes), and set `decision="KEEP"`.

**REVISE (Updated)** — When a substantive textbook change requires updates to a question: set `decision="REVISE"`. The target format shows readers BOTH the old and new wording directly inside `<STEM>`/`<A>`-`<D>`, marked up inline, so a human editor can see the tracked change at a glance without leaving the question:

- Wrap ONLY the exact span of text that changed — never the whole field — in `<DEL>...</DEL>` immediately followed by a single space and `<INS>...</INS>` containing the corrected replacement for that same span.
- Leave every unchanged word, before and after the changed span, as plain text outside any tag.
- If more than one distinct span in the same field changed (e.g. the year AND the company names), wrap each span separately with its own `<DEL>`/`<INS>` pair, in the order they appear.
- If the same changed term/fact appears more than once across the STEM and options, EVERY occurrence must get its own `<DEL>`/`<INS>` pair — not just the first one. See the Completeness Check below; this is verified per-item, not assumed.
- `<DEL>` must contain the *literal original wording* from the input `<ITEM>` — copy it exactly, do not paraphrase it — and `<INS>` must contain the corrected wording. Do not swap them and do not omit either one.
- Structural pattern — if the input `<STEM>` reads `N. In [old year], [old entity A], [old entity B], and [old entity C] achieved [old outcome] because they did which of the following?` and the new edition changes the year and the named entities, output:
  `<STEM>N. <DEL>In [old year], [old entity A], [old entity B], and [old entity C] achieved [old outcome]</DEL> <INS>In [new year], [new entity A], [new entity B], and [new entity C] achieved [new outcome]</INS> because they did which of the following?</STEM>`
  This is a structural pattern only — always substitute the actual old/new facts found in the specific input item and the specific textbook chapter you were given for that run. Never reuse any placeholder or bracketed example wording from these instructions as if it were real chapter content, regardless of which chapter or subject you are processing.
- Apply the same `<DEL>`/`<INS>` markup inside `<A>`-`<D>` for any distractor whose text changed (e.g. the rationale in the correct answer).
- Do NOT use `<DEL>`/`<INS>` for KEEP or REMOVE items, or for any part of a REVISE item that is unchanged.
- The full before/after comparison in prose still belongs in `<AI_REVIEW>` under `REVISIONS:` — the inline `<DEL>`/`<INS>` markup and the prose explanation are both required and serve different readers (quick visual scan vs. full rationale).

**REMOVE (Deleted)** — If a topic or question is no longer covered or supported by the new textbook edition: set `decision="REMOVE"`. Still include the full original item content in the fields (do not blank them out) so a human editor can see exactly what is being proposed for removal, and explain the reasoning in `<AI_REVIEW>`.

**CRITICAL REMINDER:** Every item from the input MUST appear in your output as exactly one `<OUTPUT_ITEM>` marked KEEP, REVISE, or REMOVE. Never omit an item.
